# Context for: OWNERSHIP INVERSION — user-owned root flake.nix with a managed "nws block"

**Question under study**: the root `flake.nix` of every workspace is currently wholesale
nws-owned (a `# nws-generated — do not edit` first line marks the WHOLE file as managed, and
regeneration rewrites every byte). User content layered on top of the generated flake — e.g.
a ROS `devShells.<system>.default` injected by `examples/overlay-ros/run.sh` — is **silently
wiped on the next fs event**. The plan will invert ownership: the flake becomes USER-owned and
nws manages only a MARKED block inside it, parsing the existing file and surgically replacing
only its own block. This maps every place the "nws owns whole file" assumption lives, what a
marker-block approach must touch, and every Golden test / README claim / example that encodes
the old contract.

**Verified facts up front** (details + lines below):

- Both generators (`generate_root_flake`, `generate_overlay_root_flake`) are **pure functions of
  their inputs** — they emit the complete file from scratch, header first. Neither ever reads
  the existing root flake text.
- The daemon's only use of the existing root flake is (a) `is_managed_root` — a **`strings.has_prefix`
  check on the first line** (root_flake.odin:359-360) — and (b) a byte-equality skip (nix_workspace.odin:1096).
- There is **no root-flake parsing anywhere** today. `parse_flake_input_names` /
  `parse_input_line_head` / `count_braces` (root_flake.odin:236-356) parse **child** flakes
  only (for sibling-dep wiring). A block finder/injector is net-new logic.
- **nws preserves ZERO user content today.** Any file whose first line is the header is
  replaced wholesale; anything else is skipped entirely (never touched, so a user flake with no
  nws interest is safe, but a user flake that wants nws' machinery cannot have ANY custom
  top-level attr — `description`, `nixConfig`, a hand-written `devShell` — they all die).
- The workspace root inotify watch does **not** use `.ONLYDIR` (nix_workspace.odin:68-78), so a
  user's own edit to `flake.nix` (CLOSE_WRITE) triggers a sync → with the header present their
  edit is the very thing wiped.

## Focus 1 — `src/core/root_flake.odin` (361 lines) — flake-delegation backend

### Ownership + gate constants
```odin
// line 21-23
// MANAGED_ROOT_HEADER is the first line that marks a root flake.nix as
// nws-managed. A root flake without it is user-authored and never touched.
MANAGED_ROOT_HEADER :: "# nws-generated — do not edit"

// lines 356-360
// is_managed_root reports whether the given flake text starts with the
// nws-managed header on its first line. Only managed roots may be
// regenerated by the daemon; anything else is user-authored.
is_managed_root :: proc(text: string) -> bool {
	return strings.has_prefix(text, MANAGED_ROOT_HEADER)
}
```
Consequences for the inversion:
- The marker is **file-owned** (first line), not block-owned. A user file that happens to start
  with the header string is _managed_ and gets wiped; a file with any preamble before the header
  is _user_ and is never serviced. Both branches are wrong for the block design.
- `is_managed_root` is the **only** gate used by the daemon (nix_workspace.odin:1091, 1168) and
  by tests; its semantics (and name) must become "flake contains an nws block".

### `Child_Info` (lines 10-19)
```odin
Child_Info :: struct {
    name:    string,   // directory (and Nix input) name
    url:     string,   // canonical URL recorded as `# nws:` marker comment
    has_url: bool,     // false → input emitted with no marker
    deps:    []string, // input names parsed from the child's own flake.nix
}
```

### `generate_root_flake :: proc(children: []Child_Info, allocator := context.allocator) -> string` (line 38)
Pure and byte-deterministic: copies children, sorts by name (lines 45-49), then builds the whole
file into a fresh `strings.Builder`. **No existing-content parameter exists.** Structure:

```
line 52:  strings.write_string(&b, MANAGED_ROOT_HEADER)      ← the whole-file marker
line 53:  "{"
lines 54-75: inputs = { ... } — per child:
              "" + write_attr_key(name) + `.url = "path:./` + nix_escape_string(name) + `";`
              + optional ` # nws: <url>` marker (lines 64-67, the canonical-URL persistence)
              + emit_sibling_overrides(...) (line 198) → `<child>.inputs.<dep>.url = "path:./<dep>";`
            empty → `  inputs = {};` (line ~72)
line 77:  root_flake_outputs(&b, sorted[:])
line 80:  "}\n"

```
The `# nws: <url>` marker at line 64-67 is a **second, distinct** marker comment nws emits —
the child-flake marker from the old per-child scheme, now living in the root. A block design
must keep it inside the block (it is state nws reads back? no — state.json is the source of
truth; the marker is a human-readable mirror).

### `root_flake_outputs :: proc(b: ^strings.Builder, sorted: []Child_Info)` (line 87)
Emits the `outputs` delegation section (see Focus 6 of the old scout / the golden:
`outputs = { self, ... }@inputs:` … `let children = [...]` … `perSystem` … `systemsOf` …
`delegate` … `packages = delegate "packages"; devShells = ...; apps = ...; checks = ...;`).
Key structural fact: the outputs block references `inputs.${child}` — the block's correctness
is coupled to the `inputs` section existing. In block form, inputs + outputs + sibling wires
must all live inside the nws block (or the block must be split across the file, which is far
messier — the former is the natural design).

### Escaping helpers (shared, `package core`)
- `is_nix_identifier` (line 132), `nix_escape_string` (line 152), `write_attr_key` (line 174) —
  reused by the overlay generator too; a block design reuses them for the emitted block.
- `has_child_name` (185), `emit_sibling_overrides` (198).

### Existing root-flake-adjacent parsing (CHILD flakes only, but the parsing style to copy)
- `parse_flake_input_names` (line 236): **line-based, brace-counting conservative parser**
  (`count_braces` 289, `parse_input_line_head` 308, `ident_start_byte`/`ident_cont_byte` ~334/340)
  that walks only the top-level `inputs = { ... }` block and captures `NAME.url = ...` /
  `NAME = { ... }` heads. This is the repo's existing precedent for "parse a flake without a
  Nix evaluator" — a block finder would be a sibling in the same conservative style
  (line-scan for `# BEGIN nws` / `# END nws` markers, fail-open when absent).

## Focus 3 — `src/nix_workspace.odin` (1227 lines) — daemon write path

### Triggers (where sync runs)
- `add_workspace` (register path) calls `sync_workspace(state, path)` immediately (line 756) —
  a brand-new workspace gets `flake.nix` created on first event.
- Event loop: `process_inotify_event` (865) — `Q_OVERFLOW` resyncs all (872); `DELETE_SELF`/
  `MOVE_SELF` (889); and the **sheet-anchor**: any `CREATE|DELETE|MOVED_TO|MOVED_FROM|
  CLOSE_WRITE|ATTRIB` on the root watch fires `sync_workspace(state, p)` (899-905). Because
  `WATCH_MASK` (lines 68-78) has **no `.ONLYDIR`**, `CLOSE_WRITE` on `flake.nix` itself is
  included — a user saving an edit to the flake triggers regeneration. The byte-equal skip
  (1096) is the ONLY thing preventing an edit→regen→write→event→regen loop today: nws regens,
  sees identical bytes (its own output), skips. In the block design the same mechanism must
  compare the **patched** result, not the generator output.

### `atomic_write :: proc(path, text: string, logging: bool, what: string) -> bool` (lines 919-935)
```odin
atomic_write :: proc(path, text: string, logging: bool, what: string) -> bool {
	tmp := strings.concatenate({path, ".tmp"}, context.allocator)
	defer delete(tmp)
	if err := os.write_entire_file(tmp, text); err != nil {   // <path>.tmp in same dir
		os.remove(tmp)
		log_line(logging, "failed to write %s: %v", tmp, err)
		return false
	}
	if err := os.rename(tmp, path); err != nil {              // atomic swap
		log_line(logging, "failed to rename %s: %v", tmp, err)
		return false
	}
	log_line(logging, "%s %s", what, path)
	return true
}
```
Renames `flake.nix.tmp` → `flake.nix`. **The rename itself is an inotify event**
(MOVED_TO/CLOSE_WRITE) → a self-trigger, which today is broken only by the byte-equal skip.
A block-patching write must preserve byte-equality semantics (patch → compare full result →
skip if identical).

## Focus 4 — Full-file rewrite: the bug both backends share

- `MANAGED_ROOT_HEADER` wrote at root_flake.odin:52, overlay_flake.odin:77 and 85 — always byte
  0 of the emitted file.
- The daemon gates on `strings.has_prefix(existing, MANAGED_ROOT_HEADER)` (nix_workspace.odin:
  1091/1168). An existing file that passes the gate is **replaced entirely** by
  `atomic_write(fl_path, generated, ...)` (1099/1175).
- **Nothing in the codebase preserves any user-authored content in a flake that nws manages.**
  Confirmed by:
  - both generators take zero existing-text input;
  - the only "user content" that survives today is the `.nws/packages/<name>.nix` override
    files — because they live **on disk, not in the flake**, referenced via a `pathExists`
    guard the generator emits (overlay_flake.odin:177-181). That is the existing precedent for
    "user layer beside the generated machinery"; the block design applies the same idea
    *inside* the flake text.
  - the `# nws:` marker (root_flake.odin:64-67) is nws' own comment, mirror of state.json — not
    user content.
- Consequence today: `devShells.<system>.default` (or any hand-written attr) added to a managed
  root flake is gone on the next `CLOSE_WRITE`/clone/rm event. run.sh's whole inject machinery
  exists to fight this (Focus 7).

## Synthesis — integration points and what a marker-block approach must touch

### Where "nws owns whole file" lives (every assumption to invert)
1. `MANAGED_ROOT_HEADER` constant + first-line emission — root_flake.odin:23, 52; overlay_flake.odin:77, 85.
2. `is_managed_root` prefix gate — root_flake.odin:356-360; used at nix_workspace.odin:1091, 1168.
3. The straight-`atomic_write` of the generated file with no surrounding-content handling —
   nix_workspace.odin:1085-1099 (flake backend) and 1161-1175 (overlay backend).
4. The byte-equal self-trigger guard compares `existing == generated` — nix_workspace.odin:1096,
   1172; must become `existing == patch(existing, generated_block)`.
5. Full-file goldens and `is_managed_root` asserts in tests — root_flake_test.odin
   10-68/179-223/255-308/227-250 (and 65/222), overlay_flake_test.odin 26-113/147-157/230-302
   (and 111/156).
6. README ownership claims — README.md:110-117, 166-167, 428-429 (+"daemon own the workspace
   root", 173-178); examples/overlay-ros/README.md ("the dev shell is a user layer",
   regeneration-drop claim, lines 83-84) and run.sh (Focus 7).
7. `WATCH_MASK` without `.ONLYDIR` (nix_workspace.odin:68-78) — user edits to flake.nix fire
   syncs; the block design turns this from "wipe the user's edit" into "merge my block, keep
   their edit" and must keep the loop-free invariant via patched-byte-equality.

### New primitives the plan must specify (in `src/core/`, by analogy with parse_flake_input_names)
- **Block markers**: a `# BEGIN nws` / `# END nws` comment pair (or single sentinel line), e.g.
  `# nws block — managed by nws; do not edit` … `# /nws block`. MUST be on their own lines so a
  line-scanner can find them; comment-style so both generators' escaping rules are irrelevant.
- **Generator split**: refactor both `generate_root_flake` / `generate_overlay_root_flake` so the
  part they own = the block body; the surrounding `{`, `description`, user attrs come from the
  existing file.
- **Block finder**: `find_nws_block(text) -> (start, end)` — line-based conservative scan for the
  marker pair (fail-open: absent → inject).
