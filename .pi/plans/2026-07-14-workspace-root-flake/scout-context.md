# Context for: workspace root flake generation (replacing per-child flake rewrites)

## Relevant Files
- `src/nix_workspace.odin` (772 lines, `package main`) — CLI dispatch, daemon event loop, inotify handling, and the **flake sync glue** (`sync_workspace`, `local_repos`).
- `src/core/flake.odin` (183 lines, `package core`) — current line-based child-flake rewrite (`sync_flake`, `process_line`, `extract_marker`).
- `src/core/config.odin` (131 lines) — `Config{port, workspaces: [dynamic]string}`, atomic JSON load/save. No schema change likely needed.
- `src/core/url.odin` (68 lines) — percent encode/decode for the wire; unaffected by refactor.
- `tests/flake_test.odin`, `tests/config_test.odin` — unit tests, `package tests`, run via `odin test tests -collection:nwscore=src` (wired in `flake.nix` enterTest).
- `flake.nix` — devenv flake; build command `odin build src/nix_workspace.odin -file -collection:nwscore=src -out:build/nws`; enterTest also runs `tests/completions_test.sh`.

## How the current pipeline works (what must change)

1. **Trigger:** every relevant inotify event on a workspace root (CREATE/DELETE/MOVED_*/CLOSE_WRITE/ATTRIB, single non-recursive watch per workspace) funnels into `process_inotify_event` → `sync_workspace(state, path)` (`nix_workspace.odin`). There is no debounce/coalescing: each event triggers a full rescan + potential rewrite. Q_OVERFLOW rescans all workspaces.
2. **Child detection:** `local_repos(path)` lists first-level subdirectories containing `.git` or their own `flake.nix`. This function is **fully reusable as-is** for detecting children to aggregate into a root flake.
3. **Transform call site:** `sync_workspace` reads `<workspace>/flake.nix`, calls `core.sync_flake(text, local[:])`, writes back atomically via `<path>/flake.nix.tmp` + rename only if changed. **This is the single point to replace**: instead of rewriting the child/root's own flake in place, it should generate `<workspace>/flake.nix` from scratch when absent/not-nws-owned... note today the daemon *rewrites the user's existing flake.nix* — under the new model the daemon *owns* the root flake file entirely, which changes the read-modify-write contract to generate-or-update.
4. **Marker scheme:** `# nws: <canonical-url>` appended after the `;` on managed input lines; idempotent via `extract_marker`. For root flakes, markers move onto generated `inputs.<name>.url = "path:./<name>";  # nws: github:...` lines — same convention can be reused verbatim for restoring canonical URLs when clones disappear.

## What survives vs. gets replaced

**Survives unchanged:**
- All of CLI dispatch, control socket, poll loop, client buffering, config save/load, url codec, workspace add/remove/watch bookkeeping.
- `local_repos` (child detection).
- Atomic write pattern (tmp + rename) in `sync_workspace`.
- Marker concept (`# nws: <canonical>`) and `extract_marker`.

**Replaced / heavily reworked:**
- `core.sync_flake` / `process_line`: line-level rewrite of an existing flake becomes irrelevant if the root flake is fully daemon-generated. Replaced by a generator like `generate_root_flake(children []Child_Input, allocator) -> string`. However, keep some parsing ability if the planner wants to *merge* with user-authored content or preserve unknown inputs — currently nothing parses Nix beyond the `.url = "..."` line matcher, so "merging outputs" of arbitrary user flakes needs a policy decision (see Gotchas).
- `sync_workspace`: becomes "detect children → build/generate root flake content → diff & atomic write". Must also decide behavior when a pre-existing non-nws flake.nix sits at the root (currently it edits it; new model probably refuses or backs up).

## New responsibilities the refactor introduces

- **Root-flake template generation:** emit valid Nix with `inputs` (one `path:./<name>` entry per cloned child, `# nws:` marker preserving canonical URL), plus an `outputs` section that delegates/aggregates child outputs. Output-aggregation policy is unspecified in code today — planner must define it (e.g. forward each child's `packages`, `devShells`, `apps` namespaced per child? `checks`?). Nothing in the repo hints at the desired merge semantics.
- **Canonical URL source:** today the canonical GitHub URL comes from the *child flake's* original `NAME.url = "github:..."` value. If child flakes are untouched, where does the canonical URL come from? Options: parse each child's `flake.nix` for its own inputs/self URL, store in state, or derive from git remote (`git -C <name> remote get-url origin`) — none of this exists yet; `local_repos` only returns names.
- **Idempotency/diffing at whole-file level:** compare generated text against current root flake before writing; consider a `# Generated by nws. Do not edit.` header so the daemon can detect foreign files.
- **Event noise:** generating the root flake on CLOSE_WRITE of the root flake itself will trigger another event; today's rewrite has the same self-trigger but is idempotent so second pass reports `changed=false` and skips the write. The generator must be byte-deterministic to avoid an infinite rewrite loop.

## Conventions
- Odin 2026-07a; single-threaded poll loop, no threads (per-thread allocators). All `[dynamic]` state on one thread.
- Core logic goes in `src/core/` (`package core`, imported as `nwscore:core`); tests in `tests/*_test.odin` using `@(test)` + `testing.expectf`; both build and test commands need `-collection:nwscore=src`.
- Fail-open/conservative philosophy: never corrupt a flake; unparseable input passes through.
- Atomic file writes (tmp+rename). Formatting via odinfmt pre-commit hook.
- Verify with `nix build .#main` and `devenv test`.

## Gotchas
- **Self-trigger loop risk:** writing the root flake fires inotify on the same watch → resync → must be no-op second time (byte-identical output required).
- The watch mask includes ATTRIB/CLOSE_WRITE on everything in the root dir, so clone/unclone and any editor touch all trigger full resync — fine now, but generation cost grows with children count.
- Current transform preserves user-authored flake structure (comments, ordering, nested attrs). Full generation destroys any user customization of the root flake — migration story needed for existing users whose flakes already carry `# nws:` markers from the old scheme (a one-time conversion/cleanup path may be warranted).
- `local_repos` treats "has .git OR own flake.nix" as a repo; a folder with only flake.nix (no .git) counts — affects what becomes a path input.
- No symlink resolution (`normalize_path` is lexical only) — duplicate registrations via symlinks possible; irrelevant to transform but matters for per-workspace state.
- `sync_workspace` silently returns when no flake.nix exists; new generator must instead create one (or decide to wait until ≥1 child exists).
- Tests are exact-string comparisons; deterministic output formatting (ordering of inputs, indentation) should be specified and locked by tests.
